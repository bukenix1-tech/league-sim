# リーグ運営シム（段階 6）

架空の 1 部 20 クラブ・2 部 24 クラブのリーグで、自分のクラブの経営者になって何年も続けるゲーム。
試合は選手と監督の能力から計算して自動で進み、経営者はお金・年俸の予算・夏と冬の移籍と契約・監督・入場料・施設を決める。
ホーム画面に置けて、電波が無くても遊べる（PWA）。毎年、昇格と降格、引退と新人がある。
スマホのブラウザで遊ぶ前提で、静的なファイルだけで動く（サーバーの処理は無い）。何十年も続けて遊べる形を目指す。

## 道具の選び方

**ビルドの無い素の JavaScript（ES モジュール）に、JSDoc で型を付けて書いている。**
この PC には Node.js が入っておらず、それを入れなくても動いて確かめられる形にするためにこうした。
`// @ts-check` と JSDoc の型があるので、TypeScript の型チェックはそのまま効く（`npm run typecheck`）。
Vite などのビルドの道具は、ファイルが増えて必要になった時に足す。

## 動かし方（PC）

このフォルダで静的なファイルを配る簡単なサーバーを立てる（Python が入っていればよい）。
ブラウザに古いファイルを覚えさせない開発用のサーバー:

```bash
python scripts/serve.py
```

ブラウザで開く:

- `http://localhost:8000/` … はじめに自分のクラブを選ぶ。「前半を進める」で夏の補強からシーズンの半分まで進んで冬の移籍の時期で止まり、「後半を進める」で残りとシーズンの後まで進む。「10 年進める」は冬で止まらない。タブで「経営（お金・人気・オーナーの目標と信頼・監督の交代・年俸の予算・入場料・施設・ほかのクラブからの誘い・前のシーズンの収支）」「移籍（補強のおまかせ／自分で、海外からのオファー、自分の選手の契約の更新・売る・解除、取れる選手。選手ごとに、いる国・何部・クラブを出し、国内・海外・フリーでしぼれる）」「順位（1 部・2 部、プレーオフ）」「個人（得点・アシスト）」「クラブ（監督と選手、選手を押すと能力と通算）」「試合（進めた直後のシーズンだけ）」「歴代（自分のクラブの歩み・優勝・昇格・降格・得点王）」を見られる。
  1 年ごとと予算を変えたときにブラウザの中に自動でセーブし、次に開くと続きから始まる。下の「セーブ・新しく始める」で書き出し・読み込み・新しく始める
- `http://localhost:8000/sim.html` … 1 シーズンを 1000 回回したまとめと、何十年も続けたまとめ（優勝の偏り・能力と選手の数・お金・重さ）
- `http://localhost:8000/tests.html` … 計算の部分の試験

Node.js を入れた場合は、同じ計算と試験を Node でも回せる:

```bash
npm test
```

```bash
npm run season -- 42
```

```bash

```

```bash

```

## スマホで確かめる

**同じ Wi-Fi から開く**（公開しない・おすすめ）:

1. PC で `python scripts/serve.py` を実行する（Windows のファイアウォールが聞いてきたら「プライベート ネットワーク」だけ許可する）
2. PC の IP アドレスを調べる（PowerShell で `ipconfig` の「IPv4 アドレス」、例 192.168.1.23）
3. スマホのブラウザで `http://192.168.1.23:8000/` を開く

**GitHub Pages で開く**（公開中）: https://bukenix1-tech.github.io/league-sim/

main ブランチに push すると、1〜2 分でこのページが新しくなる（Settings → Pages で main ブランチのルートを配る設定）。

**ホーム画面に置く**: iPhone は Safari で開いて共有ボタン →「ホーム画面に追加」、Android は Chrome のメニュー →「ホーム画面に追加」（または「アプリをインストール」）。
一度開けば、あとは電波が無くても開ける。新しい版を出したときは、一度電波のあるところで開くと裏で新しいファイルを取り、次に開いたときから新しい版になる。

**新しい版を出すとき**: `sw.js` の `VERSION` と、`index.html` の `style.css?v=` と `app.js?v=`（`sw.js` の `FILES` の中も）を同じだけ上げる。アイコンを変えたら `python scripts/make_icons.py`。

## しくみ

計算 (`src/engine/`) と画面 (`src/ui/`) を分けている。計算の部分は DOM を使わないので、ブラウザでも Node でも同じに動く。

- **選手** (`players.js`): 位置は GK・DF・MF・FW。能力は 7 項目（シュート・パス・ドリブル・守備・スピード・スタミナ・キーパー）で 1〜99、野球ゲームのように S〜G でも出す。
  特徴は 0〜2 個（決定力・チャンスメーカー・ケガしにくい・ケガしやすい・鉄人・早熟・晩成）。総合力は位置ごとに効く能力の重み付きの平均
- **年齢** (`players.js` の `agePlayer`): 27 歳ごろ（早熟は 25・晩成は 29）まで、伸びしろ (`potential`) との差を毎年 3 割ずつ埋めて伸びる。その後 3 年はほぼ変わらず、そこから衰える（スピードとスタミナは速く落ちる）。段階 3 でシーズンの間に使う
- **世界** (`world.js`): クラブの `level` をもとに、1 クラブ 22 人（GK 3・DF 7・MF 7・FW 5）と監督 1 人を作る。主力ほど強く、控えほど弱い。名前は `data/names.json` の名と姓の組み合わせで、重ならないようにする
- **監督** (`world.js` の `STYLES`): 型（バランス 4-4-2・攻撃的 4-3-3・守備的 5-3-2・育成 4-4-2）と采配の力。型で攻撃力と守備力が ±5% ほど、采配で ±5% ほど変わる。育成の型は段階 3 で若手の伸びを良くする
- **先発と強さ** (`lineup.js`): 監督が、けが人を除いて「能力 × 体調」の高い順に、型の並びどおり 11 人を選ぶ（足りない位置は別の位置の選手で埋める）。
  先発の能力から攻撃と守備の評価を出し、`exp((評価 − 66) × 0.03)` を攻撃力・守備力にする
- **試合** (`match.js`): 得点の期待値を
  - ホーム = `BASE_GOALS × HOME_ADVANTAGE × ホームの攻撃力 ÷ アウェーの守備力`
  - アウェー = `BASE_GOALS × AWAY_FACTOR × アウェーの攻撃力 ÷ ホームの守備力`

  で出し、それぞれポアソン分布から点数を引く。点を取った選手は位置とシュートで、アシストは位置とパスで決める
- **疲れとけが** (`season.js`): 先発すると体調が 12〜30 減り（スタミナが高いほど減らない）、毎節 12 戻る。体調が低いと力が落ち（最大 2 割）、監督は元気な控えを使う。
  先発 1 人が 1 試合でけがをする確率は 3.5% が基準で、疲れや特徴で変わる。休みは多くが 1〜2 節、たまに長い
- **順位表** (`table.js`): 勝ち 3・引き分け 1。勝ち点 → 得失点差 → 総得点 の順に並べる
- **何年も続ける** (`league.js`): 1 年は「1 部（38 節）と 2 部（46 節）のシーズン → 2 部のプレーオフ → 昇格と降格 → シーズンの間」。
  1 部の下 3 クラブが降格、2 部の上 2 クラブとプレーオフ（3〜6 位、準決勝はホームとアウェー、決勝は中立の場所、同点なら PK）の勝者が昇格
- **前半と後半** (`league.js` の `playFirstHalf` と `playSecondHalf`): 前半は「シーズン前（夏）→ 1 部 19 節・2 部 23 節」まで。途中の順位表と選手の記録はセーブに入れる (`midSeason`)。
  後半は「残りの節 → プレーオフ → お金と人気 → オーナーの評価とクビ → 昇格と降格 → シーズンの後」。`playYear` は 2 つを続けて回す（冬で止まらない）
- **冬の移籍**: 前半と後半の間に、自分のクラブは取る・売る・解除する・契約を更新する・監督を交代することができる。冬に取った選手は後半の試合から出る。おまかせの補強と年俸の予算は夏だけ。コンピューターのクラブは冬には動かない
- **シーズンの前（夏）** (`offseason.js` の `runPreseason`):
  - 年俸の予算を決める。おまかせは「収入の見込みの 7 割弱 + お金の残りの 4 分の 1、借金があれば減らす」。予算で目指せる強さ (`levelFromBudget`) に、クラブの規模 (`level`) が 1 年で 7 割近づく（揺れあり）。まれに新しいオーナーが来て 80〜200 億円を入れる
  - 契約が切れた選手（残り 0 年）: コンピューターのクラブは、力が足りていれば更新する。ただしクラブの規模を 8 以上上回るスターは 7 割の確率で断って出ていく。出た選手はフリーになる（33 歳以上は引退）
  - 総合力 86 以上の選手は、海外のクラブに引き抜かれることがある（86 で 10%、1 上がるごとに +3%）。移籍金はクラブに入る
  - 力の足りない選手と、位置ごとの人数を超えた分を放出し、足りない位置を埋める。フリーの選手で合う人がいれば先に取り、いなければ若手（17〜19 歳）と即戦力（21〜29 歳）を作る
  - 施設に余裕があれば大きくする。その年の調子を決める（攻撃力と守備力に掛かる。揺れは 12%）
  - 自分のクラブが「自分で」補強のときは、上のことを自動ではせず、夏に「移籍」タブで決めたとおりになる。試合に必要な人数（GK 2・DF 6・MF 6・FW 3）に足りない分だけ育成の若手が入る
- **契約と移籍** (`contracts.js`, `market.js`): 契約は年数と年俸。年俸は契約したときの力で決まる。移籍金は年俸・年齢・伸びしろ・契約の残りから決まる（残り 0 年なら 0）。
  自分のクラブは夏に、フリーの選手や他のクラブの選手を取る（移籍金を払う。手元のお金と、収入の見込みの 3 割まで借金できる）、他のクラブに売る、契約を解除する（残りの年俸の半分を払う）、契約を更新する。
  クラブの規模を 8 以上上回る選手は来てくれず、更新も断る。選手は 26 人まで
- **施設** (`finance.js`): スタジアム（1 回 25 億円で 5000 席、90000 席まで）・練習場（選手の伸びが 1 段ごとに 1 割増し）・育成（育成の若手が強く、伸びしろも大きくなる）。練習場と育成は 1〜5 段で、上げる費用は 15 億円 × 次の段。毎年の維持費がかかる
- **監督の交代** (`market.js` の `hireManager`): シーズンの後に、雇える監督の候補が 4 人出る（采配は今のクラブの規模の前後）。夏と冬に、今の監督に年俸 1 年分の違約金を払って交代できる
- **入場料** (`finance.js` の `TICKET_LEVELS`): 安い（値段 0.75 倍・来たい人 1.2 倍・人気が毎年 2% 増える）・普通・高い（1.35 倍・0.8 倍・人気が毎年 2% 減る）。コンピューターのクラブは普通
- **クビ** (`league.js`): オーナーの信頼が 10 以下になるか、借金が収入の見込みの 6 割を超えるとクビ。2 部の小さいクラブ 3 つから声がかかり、選んだクラブでやり直す（リーグはそのまま続く）。信頼が 30 以下になると経営タブで知らせる
- **海外のリーグ** (`abroad.js`): スペイン・ドイツ・イタリア・フランス（国は実在、クラブと選手は架空）の 1 部と 2 部。いつも 96 人の選手が移籍の一覧に出て、毎年 4 分の 1 ほど入れかわる。
  海外の選手を取ると移籍金は海外のクラブに払う（リーグの外へ出る）。海外の選手を取れるのは自分のクラブだけで、コンピューターのクラブの動きは変わらない（自分のクラブが無い 50 年の確かめでは作らない）。
  海外に引き抜かれた選手や、海外からのオファーを受けて売った選手も、この一覧に入る。このゲームのリーグの国は「イングランド」
- **いまやること** (`guide.js`): 経営タブの一番上に、いまの時期（夏・冬・クビ）と自分のクラブの様子から、やれること・やるべきことを出す（契約切れ・足りない位置・借金・信頼・目標と今の順位など。先にやるべきことには「！」）。最初の年は「はじめての方へ」で 1 年の流れも出す。ページの下に「遊び方」
- **電波が無くても開ける** (`sw.js`): 最初に開いたときにゲームのファイルを全部しまい、次からはしまったものを使う。セーブはもともとブラウザの中なので、電波が無くても続きから遊べる
- **誘いとオファー** (`league.js`): オーナーの目標を達成して信頼が 70 以上なら、規模が少し大きいクラブ 2 つまでから誘われ、夏のうちなら移れる。自分のクラブの総合力 86 以上の選手には、海外のクラブからオファーが届き、受けるかを決める
- **お金と人気** (`finance.js`): 単位は億円と万人
  - 入るお金: 入場料（観客 × 入場料 × ホームの試合数。観客は人気で決まりスタジアムの席の数まで）・放映権（1 部 20〜39 億、2 部 14〜23 億。降格したクラブは 2 年間 12 億の上乗せ＝パラシュート）・スポンサーとグッズ（人気で決まる）
  - 出るお金: 年俸（総合力 60 で 3 億、10 上がるごとに約 1.8 倍。総合力 78 を超えるスターは、強さの割に急に高くなる）・監督の年俸・運営費・施設の維持費
  - オーナーへの配当: 手元のお金が収入の 1.5 倍を超えたら、超えた分の 3 割をオーナーが持っていく（お金が貯まりすぎないように）
  - 優勝したクラブは、選手の年俸が 15% 上がる（優勝の手当てと契約の見直し）
  - 人気: 順位で決まる値に毎年 12% ずつ近づく。1 部の上の方で大きく増え、10 位より下はあまり変わらない。2 部より 1 部の方が高い
  - 決められる予算の幅: 収入の見込みの 3 割から、9 割 + お金の残りの半分まで。借金がふくらむと上限が下がる
- **オーナー** (`owner.js`): シーズン前に、部の中でのクラブの規模の順位から目標（優勝・6 位以内・10 位以内・残留／昇格・プレーオフ・12 位以内・18 位以内）を出す。
  達成すると信頼が上がり、外すと下がる（0〜100）。クビは段階 6 で足す
- **シーズンの後** (`offseason.js` の `runOffseason`):
  - 選手が 1 つ年を取って伸びる・衰える（育成の監督のクラブは若手が 2 割よく伸びる）。33 歳から引退が始まり、38 歳で全員引退。抜けた分は次のシーズン前に補強する
  - 契約の残りが 1 年減る。フリーの選手も年を取る（150 人まで残す）
  - 監督は 70 歳で、60 歳を過ぎるとたまに辞め、新しい監督が来る。コンピューターのクラブは、規模の順位より 6 以上下で終わると 6 割の確率で監督を解任する
  - 監督の采配は ±10% ほど効く
- **セーブ** (`save.js`, `src/ui/storage.js`): リーグ全体を 1 つの JSON にして、ブラウザの IndexedDB に 1 つしまう。書き出したファイルも同じ形。
  版の番号 (`version`) を持たせ、形を変えたら `save.js` に古い版を直す手順を足す。いまは版 5（版 1〜4 のセーブは、読むときにお金・施設・契約・監督の候補などを足して直す。海外の選手の一覧は読んだあとに作る）。細かい試合の結果はセーブに入れず、毎年の順位表・得点とアシストの上位 10 人・昇格と降格・プレーオフだけ残す
- **乱数** (`rng.js`): 種を指定できる乱数（mulberry32）。同じ種なら同じ選手・同じ流れになる
- **クラブのデータ** (`data/clubs.json`): 1 部と 2 部に分けて、id・名前・短い名前・`level`（始めのクラブの規模）。**値は全部仮で、名前は架空**

## 1000 シーズンのまとめ（種 = 1）

1 部だけ、毎回選手と監督を作り直して 1 シーズン回した平均（段階 2 で測ったもの）。

| | 結果 | 本物の目安 |
|---|---|---|
| 優勝クラブの勝ち点 | 90.4（最小 75・最大 109） | 85〜95 |
| 1 試合の平均得点 | 2.69 | 約 2.7 |
| 引き分けの割合 | 22.6% | 約 25% |
| ホームの勝ちの割合 | 44.1% | 約 45% |
| 得点王の得点 | 26.2（最小 17・最大 48） | 20〜30 |
| アシスト王 | 15.2 | 12〜20 |
| 1 クラブのけが | 18.8 件 | 15〜25 件（数え方で変わる） |
| 1 クラブで先発した人数 | 18.0 人 | （途中出場はまだ無い） |

- 引き分けが少し少ないのは、両クラブの点数を別々に引くポアソン分布のよく知られた癖。後で「0-0 や 1-1 を少し出やすくする」補正（Dixon-Coles）を足せる
- 年齢の曲線（18 歳で総合 55 の選手を育てた平均）: 18 歳 54.5 → 27 歳 63.9 → 30 歳 63.7 → 33 歳 57.8 → 36 歳 46.9

## 50 年続けたまとめ（段階 5・6 は種 1〜8 の平均、カッコは一番少ない〜多い）

| | 段階 6 | 段階 5 | 段階 4 | 段階 3 | 本物の目安 |
|---|---|---|---|---|---|
| 優勝したクラブの数 | **11.6**（10〜14） | 10.9（9〜14） | 4〜6 | 7〜9 | 10〜15 |
| 50 年ずっと 1 部にいたクラブ | **4.3**（3〜6） | 3.3（2〜5） | 8〜9 | 5〜7 | 3〜5 |
| 一番多く優勝したクラブ | 29%（24〜38%） | 37%（24〜52%） | 36〜70% | 38% | 30% くらいまで |
| 昇格したクラブが次の年も残る割合 | 61%（57〜66%） | 64%（61〜67%） | 49〜56% | 55% | 55〜65% |
| 優勝クラブの勝ち点 | 84.3（82.4〜86.5） | 85.2（83.4〜87.6） | 85.9 | 85.8 | 85〜95 |

段階 6 でシーズンを前半と後半に分けた（後半は別の乱数で回る）が、数字は段階 5 とほぼ同じで、目安の中に収まっている。お金もリーグ全体で 1700〜2300 億円（50 年目）と、段階 5 と同じくらい。

**強いクラブの固まりは、段階 5 で目安に届いた。** 直し方（段階 4 では「強いクラブほど人気と収入が増え、お金が貯まって予算を上げられる」ことで固まっていた）:

1. **スターの年俸を高くした**: 総合力 78 を超えると、年俸が強さの割に急に高くなる。強いクラブほどお金の割に強くなりにくい
2. **お金を貯めこみすぎないようにした**: 手元のお金が収入の 1.5 倍を超えたら、超えた分の 3 割をオーナーへの配当にする（移籍金でお金が増え続けて、規模の上限まで強くなるクラブが出たため）
3. **人気が効く度合いを弱め、1 部の上の方だけで大きく増える形にした**: スポンサーとグッズは人気の 0.7 乗。10 位より下は人気がほとんど同じになり、中位のクラブも降格しうる
4. **年ごとの調子の波（12%）と、監督の効き（±10%）・コンピューターのクラブの監督の解任を足した**: 何年か続く好不調ができる
5. **優勝したクラブは選手の年俸が 15% 上がる**: 連覇するほどお金がきつくなる
6. **規模がお金に 1 年で 7 割近づく**: 昇格したクラブが 1 部の収入で早く強くなり、残留しやすくなる
7. スター選手（総合力 86 以上）が海外のクラブに引き抜かれる。契約の切れたスターは、小さいクラブには残らない

ほかの数字（種 1）:

- **お金は増えすぎず、無くならない**: リーグ全体の手元のお金は 1000〜2500 億円の間で上下し、増え続けも減り続けもしない（種 1〜8 の 50 年目は 1400〜2400 億円）。借金のクラブはいつも 2〜5 クラブ。一番の借金は −128 億円
- **能力**: 上位 11 人の総合力の平均は、1 部 68.5 → 68.2、2 部 56.1 → 54.7（はじめの 5 年 → おわりの 5 年）
- **選手は足りなくならない**: シーズン中は 1 クラブ 22 人（自分で補強しているクラブは 17〜26 人）。フリーの選手を含めて 1000 人ほど
- **重さ**: 1 年 60〜120 ミリ秒、セーブは 50 年で 519 KB
- 始めは 2 部だったクラブが 1 部で優勝することもある（種 1 では 3 クラブ）

## 方針

- **プレイヤーはクラブの経営者**（オーナー・GM）。試合の作戦は監督に任せて自動で進み、経営者はお金・選手の獲得と放出・施設・監督を決める。長く遊ぶ目標は、2 部の小さなクラブを 1 部の優勝まで育てること。中身は [docs/経営の案.md](docs/経営の案.md)
- **長く遊べる**: 何十年回しても重くならないよう、シーズンごとの記録（順位・優勝）は残し、細かい試合の記録は捨てる。セーブはブラウザの中（IndexedDB）に版の番号付きで保存し、書き出しと読み込みもできるようにする
- **それらしさは野球ゲームのペナントモードくらい**: リーグの形と得点・引き分けの割合は本物に合わせる。お金や契約を細かく再現する経営シムにはせず、分かりやすさとテンポを優先する
- **名前は架空**: クラブ名も選手名も作った名前。選手名は姓と名の組み合わせで作り、何十年たっても足りなくならないようにする
