# リーグ運営シム（段階 3）

架空の 1 部 20 クラブ・2 部 24 クラブのリーグを、選手と監督の能力から計算して何年も続けるゲームの土台。毎年、昇格と降格、引退と新人がある。
スマホのブラウザで遊ぶ前提で、静的なファイルだけで動く（サーバーの処理は無い）。何十年も続けて遊べる形を目指す。

## 道具の選び方

**ビルドの無い素の JavaScript（ES モジュール）に、JSDoc で型を付けて書いている。**
この PC には Node.js が入っておらず、それを入れなくても動いて確かめられる形にするためにこうした。
`// @ts-check` と JSDoc の型があるので、TypeScript の型チェックはそのまま効く（`npm run typecheck`）。
Vite などのビルドの道具は、ファイルが増えて必要になった時に足す。

## 動かし方（PC）

このフォルダで静的なファイルを配る簡単なサーバーを立てる（Python が入っていればよい）:

```bash
python -m http.server 8000
```

ブラウザで開く:

- `http://localhost:8000/` …「1 年進める」「10 年進める」で年を進める。タブで「順位（1 部・2 部、プレーオフ）」「個人（得点・アシスト）」「クラブ（監督と選手、選手を押すと能力と通算）」「試合（進めた直後のシーズンだけ）」「歴代（優勝・昇格・降格・得点王）」を見られる。
  1 年ごとにブラウザの中に自動でセーブし、次に開くと続きから始まる。下の「セーブ・新しく始める」で書き出し・読み込み・新しく始める
- `http://localhost:8000/sim.html` … 1 シーズンを 1000 回回したまとめと、何十年も続けたまとめ（優勝の偏り・能力と選手の数・重さ）
- `http://localhost:8000/tests.html` … 計算の部分の試験

Node.js を入れた場合は、同じ計算と試験を Node でも回せる:

```bash
npm test
```

```bash
npm run season -- 42
```

```bash
npm run sim -- 1000 1
```

```bash
npm run long -- 50 1
```

## スマホで確かめる

**同じ Wi-Fi から開く**（公開しない・おすすめ）:

1. PC で `python -m http.server 8000 --bind 0.0.0.0` を実行する（Windows のファイアウォールが聞いてきたら「プライベート ネットワーク」だけ許可する）
2. PC の IP アドレスを調べる（PowerShell で `ipconfig` の「IPv4 アドレス」、例 192.168.1.23）
3. スマホのブラウザで `http://192.168.1.23:8000/` を開く

**GitHub Pages で開く**（公開中）: https://bukenix1-tech.github.io/league-sim/

main ブランチに push すると、1〜2 分でこのページが新しくなる（Settings → Pages で main ブランチのルートを配る設定）。
ホーム画面に置く（PWA）には https が要るので、こちらを使う。

## しくみ

計算 (`src/engine/`) と画面 (`src/ui/`) を分けている。計算の部分は DOM を使わないので、ブラウザでも Node でも同じに動く。

- **選手** (`players.js`): 位置は GK・DF・MF・FW。能力は 7 項目（シュート・パス・ドリブル・守備・スピード・スタミナ・キーパー）で 1〜99、野球ゲームのように S〜G でも出す。
  特徴は 0〜2 個（決定力・チャンスメーカー・ケガしにくい・ケガしやすい・鉄人・早熟・晩成）。総合力は位置ごとに効く能力の重み付きの平均
- **年齢** (`players.js` の `agePlayer`): 27 歳ごろ（早熟は 25・晩成は 29）まで、伸びしろ (`potential`) との差を毎年 3 割ずつ埋めて伸びる。その後 3 年はほぼ変わらず、そこから衰える（スピードとスタミナは速く落ちる）。段階 3 でシーズンの間に使う
- **世界** (`world.js`): クラブの `level` をもとに、1 クラブ 22 人（GK 3・DF 7・MF 7・FW 5）と監督 1 人を作る。主力ほど強く、控えほど弱い。名前は `data/names.json` の名と姓の組み合わせで、重ならないようにする
- **監督** (`world.js` の `STYLES`): 型（バランス 4-4-2・攻撃的 4-3-3・守備的 5-3-2・育成 4-4-2）と采配の力。型で攻撃力と守備力が ±5% ほど、采配で ±5% ほど変わる。育成の型は段階 3 で若手の伸びを良くする
- **先発と強さ** (`lineup.js`): 監督が、けが人を除いて「能力 × 体調」の高い順に、型の並びどおり 11 人を選ぶ（足りない位置は別の位置の選手で埋める）。
  先発の能力から攻撃と守備の評価を出し、`exp((評価 − 66) × 0.03)` を攻撃力・守備力にする
- **試合** (`match.js`): 得点の期待値を
  - ホーム = `BASE_GOALS × HOME_ADVANTAGE × ホームの攻撃力 ÷ アウェーの守備力`
  - アウェー = `BASE_GOALS × AWAY_FACTOR × アウェーの攻撃力 ÷ ホームの守備力`

  で出し、それぞれポアソン分布から点数を引く。点を取った選手は位置とシュートで、アシストは位置とパスで決める
- **疲れとけが** (`season.js`): 先発すると体調が 12〜30 減り（スタミナが高いほど減らない）、毎節 12 戻る。体調が低いと力が落ち（最大 2 割）、監督は元気な控えを使う。
  先発 1 人が 1 試合でけがをする確率は 3.5% が基準で、疲れや特徴で変わる。休みは多くが 1〜2 節、たまに長い
- **順位表** (`table.js`): 勝ち 3・引き分け 1。勝ち点 → 得失点差 → 総得点 の順に並べる
- **何年も続ける** (`league.js`): 1 年は「1 部（38 節）と 2 部（46 節）のシーズン → 2 部のプレーオフ → 昇格と降格 → シーズンの間」。
  1 部の下 3 クラブが降格、2 部の上 2 クラブとプレーオフ（3〜6 位、準決勝はホームとアウェー、決勝は中立の場所、同点なら PK）の勝者が昇格
- **シーズンの間** (`offseason.js`):
  - クラブの規模 (`level`) が、順位で決まる値に毎年 2 割ずつ近づく（揺れあり）。昇格すると少し大きくなり、まれに新しいオーナーが来て急に大きくなる
  - 選手が 1 つ年を取って伸びる・衰える（育成の監督のクラブは若手が 2 割よく伸びる）。33 歳から引退が始まり、38 歳で全員引退
  - クラブの規模に比べて力の足りない選手を年 2 人まで放出する（移籍は段階 5 で作る）
  - 足りない位置を、若手（17〜19 歳）と即戦力（21〜29 歳）で半分ずつ埋める。強さはクラブの規模で決まる
  - 監督は 70 歳で、60 歳を過ぎるとたまに辞め、新しい監督が来る
- **セーブ** (`save.js`, `src/ui/storage.js`): リーグ全体を 1 つの JSON にして、ブラウザの IndexedDB に 1 つしまう。書き出したファイルも同じ形。
  版の番号 (`version`) を持たせ、形を変えたら `save.js` に古い版を直す手順を足す。細かい試合の結果はセーブに入れず、毎年の順位表・得点とアシストの上位 10 人・昇格と降格・プレーオフだけ残す
- **乱数** (`rng.js`): 種を指定できる乱数（mulberry32）。同じ種なら同じ選手・同じ流れになる
- **クラブのデータ** (`data/clubs.json`): 1 部と 2 部に分けて、id・名前・短い名前・`level`（始めのクラブの規模）。**値は全部仮で、名前は架空**

## 1000 シーズンのまとめ（種 = 1）

1 部だけ、毎回選手と監督を作り直して 1 シーズン回した平均（段階 2 で測ったもの）。

| | 結果 | 本物の目安 |
|---|---|---|
| 優勝クラブの勝ち点 | 90.4（最小 75・最大 109） | 85〜95 |
| 1 試合の平均得点 | 2.69 | 約 2.7 |
| 引き分けの割合 | 22.6% | 約 25% |
| ホームの勝ちの割合 | 44.1% | 約 45% |
| 得点王の得点 | 26.2（最小 17・最大 48） | 20〜30 |
| アシスト王 | 15.2 | 12〜20 |
| 1 クラブのけが | 18.8 件 | 15〜25 件（数え方で変わる） |
| 1 クラブで先発した人数 | 18.0 人 | （途中出場はまだ無い） |

- 引き分けが少し少ないのは、両クラブの点数を別々に引くポアソン分布のよく知られた癖。後で「0-0 や 1-1 を少し出やすくする」補正（Dixon-Coles）を足せる
- 年齢の曲線（18 歳で総合 55 の選手を育てた平均）: 18 歳 54.5 → 27 歳 63.9 → 30 歳 63.7 → 33 歳 57.8 → 36 歳 46.9

## 50 年続けたまとめ（種 = 1）

| | 結果 | 本物の目安 |
|---|---|---|
| 優勝したクラブの数 | 7（種 2〜4 では 7〜9） | 50 年で 10〜15 くらい |
| 一番多く優勝したクラブ | 19 回（38%） | 30% くらいまで |
| 一番長い連覇 | 4 連覇（種 2〜4 では 6〜7） | 3〜4 |
| 50 年ずっと 1 部にいたクラブ | 7（種 2〜4 では 5〜6） | 3〜5 |
| 昇格したクラブが次の年も残る割合 | 55%（種 2〜4 では 50〜55%） | 55〜65% |
| 優勝クラブの勝ち点 | 85.8 | 85〜95 |

- **能力の分布は崩れない**: 各クラブの上位 11 人の総合力の平均は、1 部 70.3 → 71.3、2 部 57.5 → 55.8（はじめの 5 年 → おわりの 5 年）。一番うまい選手は 90〜95 のまま
- **選手は足りなくならない**: いつも 968 人（44 クラブ × 22 人）。平均年齢は 26.5 歳のまま、21 歳以下は 141 人 → 192 人と少し増える
- **重くならない**: 1 年 50〜110 ミリ秒（スマホではこの数倍）、セーブは 50 年で 445 KB。記録が 1 年に 3 KB ほど増える
- **気になる点**: 本物より強いクラブが入れ替わりにくい（優勝クラブの数が少なく、連覇が長め）。強さはクラブの規模でほぼ決まり、規模の動きがゆっくりなため。段階 5 の移籍とお金で、成功したクラブから選手が引き抜かれる・お金の使い方で差がつく形にすると、もっと動くはず

## 方針

- **プレイヤーはクラブの経営者**（オーナー・GM）。試合の作戦は監督に任せて自動で進み、経営者はお金・選手の獲得と放出・施設・監督を決める。長く遊ぶ目標は、2 部の小さなクラブを 1 部の優勝まで育てること。中身は [docs/経営の案.md](docs/経営の案.md)
- **長く遊べる**: 何十年回しても重くならないよう、シーズンごとの記録（順位・優勝）は残し、細かい試合の記録は捨てる。セーブはブラウザの中（IndexedDB）に版の番号付きで保存し、書き出しと読み込みもできるようにする
- **それらしさは野球ゲームのペナントモードくらい**: リーグの形と得点・引き分けの割合は本物に合わせる。お金や契約を細かく再現する経営シムにはせず、分かりやすさとテンポを優先する
- **名前は架空**: クラブ名も選手名も作った名前。選手名は姓と名の組み合わせで作り、何十年たっても足りなくならないようにする

## 次の段階の予定

スマホで遊ぶゲームなので、画面は最後にまとめて作らず、段階ごとに少しずつ足す。

1. ~~1 シーズンと順位表~~
2. ~~選手と監督~~（途中出場はまだ無い）: 選手の能力は 5〜8 項目と特徴いくつか。クラブの強さを選手から出す。得点王・アシスト、けが、疲れ。年齢による伸びと衰え。監督にも能力と型（攻撃的・守備的・若手を育てる）があり、試合は監督に任せて自動で進む
3. ~~何年も続ける~~（いまここ）: 2 部を足し、下位 3 クラブが降格・2 部から 3 クラブが昇格（1 枠はプレーオフ）。引退と新人。セーブと書き出し。50 年回して、強さが 1 クラブに偏りすぎないか・選手が足りなくならないかを確かめる道具
4. 経営の土台: 自分のクラブを選ぶ（2 部の小さなクラブからも始められる）。お金の出入り（入場料・放映権・スポンサー・グッズ／年俸）、年俸の予算、人気、オーナーの期待と評価
5. 選手と施設を動かす: 夏と冬の移籍の時期に選手を取る・売る（移籍金）。契約の交渉（年数と年俸、契約切れで出ていく）。施設（スタジアム・練習場・育成）への投資。成績が良いと別のクラブから誘われる
6. 仕上げ: ホーム画面に置いて、電波が無くても遊べるようにする（PWA）。「あとで」にした項目（監督の雇用と解任、入場料の値段、クビ）を足す

経営の中身の詳しい決まりは [docs/経営の案.md](docs/経営の案.md)。
